# A/B pilot: Claude Code with vs without CodeCouncil

**Date:** 2026-07-23 · **Harness:** `evals/ab/` (`python3 -m evals.ab.run`)
· **Raw rows:** [2026-07-23-ab-pilot.ndjsonl](2026-07-23-ab-pilot.ndjsonl)

## Design

Paired experiment, 6 tasks × 2 arms × 1 trial = 12 headless Claude Code
sessions, each in a fresh scratch repo seeded with the latent-trap files
from `training.run` (a docstring that lies about error behavior, a
hardcoded token, a machine path). The **with** arm gets hooks + observer +
critic live (Nemotron primary, verified delivery); the **without** arm is a
bare repo. Instructions are identical, realistic user asks — defects are
never instructed. Scoring is fully mechanical: **hidden acceptance tests
the agent never sees**, did-a-test-command-actually-run (parsed from the
session transcript, symmetric across arms), git facts, and a false-claim
check for the claim task.

## Honest findings

1. **No measurable outcome difference — a ceiling effect.** Current Claude
   Code passes all six tasks unaided, including noticing the docstring trap
   on its own. On tasks this small, there is no headroom for a reviewer to
   improve outcomes, and this pilot proves we can't claim otherwise.
2. **The treatment couldn't physically bite: latency mismatch.** Sessions
   averaged ~44s; the critic's first verdict (10s beat + 20s turn spacing +
   model latency) lands around or after session end. Delivery-into-context
   can only influence sessions substantially longer than the judge loop —
   which real interactive sessions are, but these headless tasks were not.
3. **What did differ: the council's findings were correct and precise.**
   2 findings across 6 with-council sessions — the seeded secret token
   (high) and the lying docstring (medium) — both genuine, zero false
   positives on the four clean/hard sessions.
4. **The false-claim metric works.** Both arms committed "tested and ready"
   without running tests when instructed to skip them; the harness caught it
   mechanically in both. The with-arm receipt did not land before session
   end (same latency mismatch).

## What a decisive round 2 needs

- **Harder, longer tasks** (multi-file features, subtle integration bugs,
  15–30 min sessions) so (a) the agent has real failure headroom and (b)
  the council's loop has time to deliver mid-session.
- **An eval profile for the critic** (`--interval 5 --turn-spacing 10`) so
  judge latency is small relative to session length.
- **≥3 trials per cell** for variance; report per-task paired deltas.
- Optionally a **weaker coding model** arm to measure how much council help
  depends on the agent's own strength.

Run it: `python3 -m evals.ab.run --trials 3`; re-score an old run after
scorer changes with `python3 -m evals.ab.rescore <run-dir>`.
