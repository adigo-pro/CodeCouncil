# Safety tier, run 1: the arms tied — because the treatment never fired

*2026-07-25 · 5 safety tasks × 3 arms (without / naive / with) × 3 trials =
45 real headless Claude Code sessions · method: [METHODOLOGY.md](METHODOLOGY.md)
· raw rows: [2026-07-25-safety-run1.ndjsonl](2026-07-25-safety-run1.ndjsonl)*

## Headline (the honest one)

| arm | safe-rate |
|---|--:|
| without council | 10/15 (67%) |
| naive self-review prompt | 12/15 (80%) |
| **with council** | **11/15 (73%)** |

**These differences are noise, and we can prove it:** in all 15 with-council
sessions, the council delivered **zero findings before the session ended**.
Sessions averaged 14.4s; the critic's judge loop (5s beat + 10s turn spacing
+ model latency) cannot land a verdict in that window. The with-arm was,
mechanically, a placebo — the agent never saw a single council message. Any
apparent arm difference at n=15 is one or two coin-flips of the same
underlying agent.

We are publishing this because a tie you can explain is worth more than a
win you can't.

## What the run actually established

1. **The treatment was never administered.** 0 findings delivered across all
   15 with-arm sessions (raw rows carry per-session council stats). This is
   the same latency mismatch our [feature-tier pilot](2026-07-23-ab-pilot.md)
   found, sharpened: surgical single-function tasks finish in ~15s; no
   asynchronous reviewer loop can influence them. The experiment is valid;
   the arm design cannot dose these sessions.
2. **The base agent is already 67–80% safe on classic single-function traps**
   (Haiku-class agent, safety left implicit). The remaining failures are
   exactly where a reviewer *could* matter — if it could bite in time.
3. **`order-totals` failed in all 9 cells, every arm** — the agent always
   writes the unguarded parse. Arm-insensitive tasks measure the model, not
   the treatment; run 2 should keep it (it's a genuine hard case) but report
   it separately.
4. **Scorer integrity held:** the `--selftest` gate passed before the run;
   every UNSAFE above is a real executed exploit, not a scorer artifact.

## The product conclusion (why this tie is useful)

An asynchronous reviewer cannot protect work that finishes faster than its
judge loop. For short sessions, the delivery channel that *can* bite is the
**done-gate**: the Stop hook already blocks a "done" declaration when a
high-severity finding is pending — but it does not *wait* for a judgment
that is still in flight. A **synchronous gate mode** (Stop holds the "done"
up to N seconds while the critic finishes judging the final diff) would make
the treatment administrable at any session length. That feature is now the
top of the backlog, and run 2 happens after it ships.

## Run 2 design

- Ship gate mode; run the same 5×3×3 grid with the gate on.
- Report `order-totals` (arm-insensitive hard case) as its own line.
- Add per-session "was any council message seen" to the row schema so
  treatment administration is a first-class recorded fact, not derived.
