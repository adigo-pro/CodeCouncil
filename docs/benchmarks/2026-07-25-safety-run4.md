## What run 4 proved

**Script-based verification works as infrastructure.** Before this run we
live-proved it directly: planted the exact `order-totals` bug class in a
scratch repo, ran one real judge+verify cycle, and got `verified` **on the
first attempt** — the model wrote a clean repro script (tries both malformed
inputs, prints `CONFIRMED:` with the actual exception, exits 0) and the
harness executed it. The tool-calling flakiness that defined run 3's
bottleneck is gone: every verification in run 4 executed a real script.
Delivered findings rose again (5 → 7).

## The residual, at higher resolution

`order-totals` is now **0-for-36** across four runs — and the rows show the
remaining cause is no longer architecture but **verifier-model discipline**:

- Most of its 9 with-arm findings verified as *"script printed no
  CONFIRMED/REFUTED marker"* — the model's script ran fine but didn't follow
  the output contract.
- Twice, the script guessed the function's signature wrong, crashed, and its
  own error handler printed `REFUTED:` — **mislabeling a script bug as a
  disproof**. Under our precision rules a refuted finding is suppressed, so
  a sloppy script actively killed a true finding. That's a real semantic
  hazard we now know to fix: the prompt must forbid printing `REFUTED:` on
  unexpected exceptions (a broken probe is not a disproof — the rule the
  probe path already enforces mechanically).

Four runs, four layers, each thinner than the last: timing → recall →
delivery-channel → execution-reliability → **script quality of the
verifying model**. Every infrastructure layer is now proven working; what
remains is model behavior at the last step of one hard task.

## The equally honest structural findings (unchanged)

- The base agent aces most single-function traps (doc-reader flipped both
  ways this run — pure variance). The instrument is saturated; arm deltas
  of ±1 flip at n=15 are noise, and we've said so in all four writeups.
- The one-shot `claude -p` harness remains the worst case for an in-session
  reviewer; the interactive product's continuous PostToolUse channel is not
  what this measures.

## Where this leaves the benchmark

We consider the safety-tier instrument **exhausted at this task difficulty**:
four runs produced a fully-proven delivery pipeline and no headroom to
demonstrate arm deltas. Next instrument change, when we take it up: harder
multi-file tasks (where the research says the 45%-insecure failures actually
live), and a verifier-prompt fix for the REFUTED-on-crash hazard. Both are
tracked; neither will be run silently — every run publishes, wins or ties.
