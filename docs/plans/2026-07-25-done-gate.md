# Done-Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When the coding agent declares "done", the Stop hook can (opt-in) hold the declaration while the critic finishes judging the session's final changes — so the council can bite at any session length. Both A/B experiments proved the async loop cannot protect work that finishes faster than a judge cycle; this closes that gap and unblocks safety run 2.

**Architecture:** The wait is I/O and lives in `hooks/peer_hook.py` (fail-open, capped, opt-in, once per session); the decision stays pure in `hooks/logic.py`. "Critic is behind" is measured mechanically: `critic-state.json.committed_offset < size(observations.ndjsonl)` (plus in-flight batch). After the wait, the existing decide() path runs against the post-wait state — a finding that lands in the window blocks exactly like any pending finding.

**Tech Stack:** stdlib only; existing seams: `hooks/peer_hook.py`, `hooks/logic.py` (pure), `hooks/ledger.py`, `.codecouncil/{state.json,critic-state.json,observations.ndjsonl,suggestions.ndjsonl}`, `evals/ab/run.py`.

## Global Constraints

- `hooks/peer_hook.py` FAILS OPEN — any error in the gate → behave as if gate off, exit 0. Non-negotiable.
- `hooks/logic.py` stays pure (no I/O) — it receives parsed facts, returns decisions.
- **Opt-in, default OFF**: no gate unless `COUNCIL_GATE_SECONDS` env (or `gate_seconds` in `~/.codecouncil/config.json`) resolves to a positive int. Default behavior byte-identical to today.
- Wait is CAPPED (resolve value clamped to [1, 120]) and runs AT MOST ONCE per session (ledger key `"gate"` mirrors the existing once-per patterns) — a stuck critic must never wedge the agent's exit.
- Fast path unchanged: if the critic is already caught up (nothing pending), the gate adds one state read, no sleep.
- Suite green at every task boundary (currently 581); README count updated when it changes.
- `.codecouncil/` here is live data — tests use temp dirs only.

### Task 1: The gate — pure decision + fail-open wait

**Files:**
- Modify: `hooks/logic.py` (pure helpers), `hooks/peer_hook.py` (wait loop + config resolution), `hooks/ledger.py` (only if a helper is needed for the `"gate"` key)
- Test: `tests/test_hooks.py`

**Interfaces:**
- `logic.gate_pending(observations_size: int, critic_offset: int, inflight: bool) -> bool` — pure: True iff the critic has unjudged material (`critic_offset < observations_size or inflight`).
- `logic.resolve_gate_seconds(env_value: str | None, config_value) -> int` — pure: 0 (off) unless a positive int resolves; clamp to [1, 120]; malformed → 0 (fail-open-by-default).
- peer_hook Stop path: if gate resolves ON and ledger's `"gate"` key unused this session and `gate_pending(...)` → poll every 1s up to the cap, re-reading critic state; stop early when caught up; mark ledger `"gate"` used; then fall through to the EXISTING decide() flow against post-wait state. Any exception anywhere → proceed as if gate off.

## Self-review notes
- Gate correctness risk is the wait loop wedging an exit — mitigated by cap + once-per-session + fail-open + opt-in; each mitigation is separately tested (T1 Step 1).
- The observer's own capture lag is accepted as a limitation (the gate waits for the CRITIC to catch up to captured observations; a diff the observer hasn't yet captured at Stop-time is out of scope — note in run-2 writeup if it shows up).
- No behavior change for every existing user: default OFF, byte-identical.
